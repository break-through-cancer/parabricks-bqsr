FUTURE FEATURE: --quantize-quals

Implement GATK ApplyBQSR-compatible dynamic quality-score quantization as a
separate mode from --static-quantized-quals.

This feature requires access to the BQSR recalibration report/table produced
by BaseRecalibrator / Parabricks BQSR.

CLI:

    --quantize-quals <N>

Semantics should match GATK ApplyBQSR:

    N == 0
        Disable dynamic quantization.

    N > 0
        Recalculate a quality-score quantization mapping using exactly N
        quantization levels.

    N < 0
        Use the quantization mapping already stored in the input BQSR
        recalibration report.

Mutual exclusion:

    --quantize-quals

must NOT be allowed together with:

    --static-quantized-quals
    --round-down-quantized

The tool should fail with a clear argument-validation error if those modes
are combined.


INPUT REQUIREMENTS

Dynamic quantization requires:

    1. The post-Parabricks ApplyBQSR BAM/CRAM whose QUAL values will be
       transformed.

    2. The BQSR recalibration report/table corresponding to that sample.

Example:

    quantize-bam \
        --input parabricks.recal.bam \
        --bqsr-recal-file recal.table \
        --quantize-quals 16 \
        --output recal.quantized.bam


RECALIBRATION REPORT

Parse the BQSR report's quantization information, including the quality-score
histogram / observation counts and the existing quantization table.

The implementation should reproduce GATK's QuantizationInfo / QualQuantizer
behavior rather than inventing a generic equal-width or equal-frequency
binning scheme.

For:

    --quantize-quals -1

(or any negative value)

use the quantization mapping already encoded in the recalibration report.

Conceptually:

    recalibrated Q
        ->
    report_quantization_mapping[Q]
        ->
    output Q


For:

    --quantize-quals N

where N > 0:

recompute a new quantization mapping with N levels using the quality-score
distribution contained in the recalibration report.

This should follow GATK's quantization algorithm exactly, including:

    - observation counts per recalibrated quality
    - empirical quality distribution
    - GATK's bin-merging / optimization procedure
    - resulting recalibrated-Q -> quantized-Q lookup table

Do NOT approximate this with:

    - equal Phred-width bins
    - simple arithmetic rounding
    - equal-count quantiles
    - nearest manually selected Q scores

unless those operations are explicitly what the corresponding GATK source
code performs.


PRESERVED LOW QUALITIES

Continue to support:

    --preserve-qscores-less-than <Q>

with default:

    --preserve-qscores-less-than 6

QUAL values below the preservation threshold should remain unchanged.

Because this tool operates after Parabricks ApplyBQSR, exact parity should
be validated against GATK, especially for non-default preservation
thresholds.


PROCESSING MODEL

Once the dynamic quantization map has been constructed, BAM processing is
the same as for static quantization:

    Build:

        mapping[0..MAX_QUAL]

    Then for every alignment record:

        for each QUAL value q:

            if q < preserve_threshold:
                new_q = q
            else:
                new_q = mapping[q]

Only modify the QUAL array.

Do not modify:

    QNAME
    FLAG
    RNAME
    POS
    MAPQ
    CIGAR
    RNEXT
    PNEXT
    TLEN
    SEQ
    auxiliary tags

except for normal BAM/CRAM header/program-record changes explicitly chosen
by the implementation.


PERFORMANCE

The expensive part of --quantize-quals should occur once at startup when
constructing the lookup table.

After that, per-base processing remains:

    new_q = mapping[old_q]

Therefore runtime should still primarily be limited by BAM/CRAM
decompression, compression, and storage I/O.

Use multithreaded HTSlib I/O where possible.


IMPLEMENTATION REFERENCE

For exact GATK compatibility, base the implementation on the current GATK
classes responsible for dynamic BQSR quantization, particularly the logic
corresponding to:

    QuantizationInfo
    QualQuantizer
    BQSRReadTransformer

The recalibration report generated by BaseRecalibrator already contains
quantization information; GATK may either use that existing information or
recompute it depending on the value supplied to --quantize-quals.


VALIDATION

Use the same:

    - original pre-BQSR BAM
    - recalibration report

for both comparison paths.

Reference path:

    GATK ApplyBQSR \
        --quantize-quals N

Test path:

    Parabricks ApplyBQSR
        ->
    custom quantizer \
        --bqsr-recal-file recal.table \
        --quantize-quals N

Test at minimum:

    --quantize-quals 0
    --quantize-quals -1
    --quantize-quals 4
    --quantize-quals 8
    --quantize-quals 16

Compare the final per-base QUAL arrays record-by-record.

Also verify that:

    --quantize-quals N
    +
    --static-quantized-quals ...

is rejected.

And verify that:

    --quantize-quals N
    +
    --round-down-quantized

is rejected.


IMPORTANT DESIGN NOTE

Treat static and dynamic quantization as two distinct modes:

    STATIC MODE
        --static-quantized-quals [...]
        [--round-down-quantized]

    DYNAMIC MODE
        --quantize-quals N
        --bqsr-recal-file recal.table

Both may share:

        --preserve-qscores-less-than

but static and dynamic quantization themselves must not run simultaneously.
